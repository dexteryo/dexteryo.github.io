§ 01

Principles

Signal density over decoration. A console shows state, not styling. Every rule-line, chip, and colour on this page encodes something true about the content; anything that encodes nothing is deleted. src: README.md §2 · 2026-10-07

Green is a claim. The phosphor accent is the same colour as [ OK ] — it marks what is healthy, verified, or added. When you see green, something is real. It is never a route colour and never a border for taste.

Colour in diagrams is a declared meaning. The ANSI palette paints routes (sync, async, data, control, external, failure) and node kinds (client, edge, service, worker, store, stream, cache, third party). Every hue a figure uses appears in its legend; a hue the legend can't name is a defect.

One family, everywhere. Body, headings, tables, labels, diagram text — all monospace. Hierarchy comes from size, weight, and colour, never from a second typeface.

Wide for evidence, narrow for prose. The shell spans the screen so diagrams, tables and grids get room; paragraphs keep a 76-character measure so they stay readable.

Motion shows direction, nothing else. Edges march the way data travels and square packets ride the hot path. That, the h1 cursor, and nothing more — all of it off under reduced motion.

§ 03

Layout

The shell (.phos-page) is fluid: full viewport width with a clamp(16px, 4vw, 64px) gutter, capped at 1920px only to stop ultra-wide stretching. Inside it, .phos-layout pairs a sticky index rail (.phos-toc, 220px) with the content from 1680px up (narrower, it would squeeze the diagrams); below that the index folds into a bordered block above the content. The index is plain anchor links — a few lines of inline script add the ▸ active marker as you scroll.

ElementWidth ruleWhy
Paragraphs, lists, pull lines--phos-measure = 76chLong mono lines are hard to track back
Diagrams, tables, stat strips, grids, codeFull content widthEvidence needs room; nothing scrolls the page sideways
Diagram SVGmin-width: var(--phos-svg-min) (1000px; set 0.8 × viewBox width per figure) inside its own scrollerDiagram text never renders under ~11px; the figure scrolls, the page does not

§ 06

Architecture diagrams

Native SVG, hand-authored, one grammar for three figure types. Nodes are <g class="phos-node <kind>"> groups whose shape says what they are — a cylinder is a store, a chamfered box is a worker, bars mark a stream, a double rule marks a cache, a dashed frame is a third party. Edges are .phos-edge <route> paths with a matching marker; .phos-flow makes the dashes march in the direction of travel, and square packets ride the one or two routes that matter. Crossings take a hop arc. Hover a node to lift it.

1 · Container architecture — top-up flow

  1. Gateway terminates TLS, verifies the JWT against auth-svc, forwards to topup-api.
  2. topup-api claims the idempotency key in idem-cache (SETNX, 24h); a replay returns the stored response.
  3. The card PSP authorises the amount (3DS2); one retry on 504 with the same key.
  4. topup-api emits TopUpRequested to ledger.events and returns 201.
  5. settle-worker consumes in batches of 50 and writes double-entry rows to ledger-db.
  6. Settlement leaves as a SEPA pain.001 batch before 16:00; three failures park it in settle.dlq.

Decision record with trade-off matrix

ADR-014

Score top-ups with a dedicated risk-engine, in shadow mode first

[PROPOSED]
Context

Fraud rules live inside topup-api and ship with every deploy. Rule changes wait for a release train; two incidents this quarter were rule regressions. src: INC-097 · INC-101

Decision

Extract scoring into risk-engine (Go, gRPC). topup-api calls it synchronously with a 40ms timeout and fails open in shadow mode for four weeks before enforcing.

Consequences
  • Rules deploy independently, minutes not days.
  • Shadow mode measures false positives before they cost revenue.
  • One more hop on the hot path: +12ms p95.
  • Fail-open must flip to fail-closed at enforcement — tracked in RISK-104.

Callouts

The idempotency key is scoped to the order, not the request — a client retry with a fresh request ID is still deduplicated.

The SEPA cut-off moves to 16:00 CET from 2026-11-01; batches after it settle next business day.

settle.dlq has no automatic redrive. Seventeen batches are waiting on a human.

Ship risk-engine in shadow mode first; enforce only after four clean weeks.

Code with file header

lib/topup/authorise.exelixir
def authorise(topup, attempt \\ 1) do
  case Psp.authorise(topup, idempotency_key: topup.order_id) do
    {:ok, auth} -> {:ok, auth}
    {:error, :timeout} when attempt < 2 ->
      Process.sleep(200)
      authorise(topup, attempt + 1)
    {:error, reason} -> {:error, reason}
  end
end
§ 08

Mermaid fallback

Native SVG is the default for architecture, sequence and state. Mermaid stays for shapes the grammar doesn't cover — ER, gantt, class, journey — pre-rendered to static SVG with this directory's dark-themed config:

$ npx -y @mermaid-js/mermaid-cli -i d.mmd -o d.svg --configFile mermaid-config.json

Pre-rendered SVG is dark-baked: pin its figure to the dark ground (background:#0A0F0C, the one sanctioned literal hex) so it survives the paper-terminal theme, and keep the DSL in a <details> beside it. Never ASCII art, however terminal the page looks.
