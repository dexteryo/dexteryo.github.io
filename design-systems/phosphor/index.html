§ 01

Principles

Signal density over decoration. A console shows state, not styling. Every rule-line, chip, and colour on this page encodes something true about the content; anything that encodes nothing is deleted. src: README.md §2 · 2026-07-30

Green is a claim. The phosphor accent is the same colour as [ OK ] — it marks what is healthy, verified, or the one emphasis. When you see green, something is real. It is never a border for taste.

One family, everywhere. Body, headings, tables, labels — all monospace. Hierarchy comes from size, weight, and colour, never from a second typeface. A serif sneaking into a heading is a defect.

Restraint over cosplay. No scanlines, no screen curvature, no flicker, no boot sequences. The motion budget is one blinking cursor (the h1, disabled under reduced motion) and the glow budget is one text-shadow (the h1, dark theme only).

Dark-first, but the printout is first-class. The default screen is the dark terminal; the light theme is a DEC paper terminal — warm paper, deep green ink, no glow. Tokens flip; components never restyle per theme.

§ 05

Diagrams

Diagrams stay vector — inline SVG or Mermaid — never ASCII art, however tempting the terminal aesthetic makes it. Architecture and funds-flow drawings reuse the DDS Tier-1 grammar recoloured with --phos-* tokens (money = ok green, manual = warn, mirror = info, blocked = crit); recolour the grammar, never reinterpret it. The Mermaid catalogue pre-renders to static SVG with this directory's dark-themed config:

$ npx -y @mermaid-js/mermaid-cli -i d.mmd -o d.svg --configFile mermaid-config.json

Pre-rendered SVG is dark-baked: pin its figure to the dark ground (background:#0A0F0C, the one sanctioned literal hex) so it survives the paper-terminal theme. Every diagram carries a caption with revision date and status.
