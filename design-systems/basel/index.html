01

Principles

The grid is the argument. Alignment is not styling; it is the visual proof that the document was composed, not accumulated. Every element sits flush-left on the column grid, and the grid may be shown (.bsl-grid-visible) because there is nothing to hide.

Type is the only ornament. Hierarchy comes from size and weight alone — a 64px headline against a 10px letterspaced label needs no colour, no rule, no icon to explain which is which. There are no italics anywhere in this system.

One red, two meanings, zero decoration. Pantone 186 is both the key emphasis and the critical state. When you see red, either something matters most or something is wrong.

Diagrams speak in primaries. Inside a figure, the constructivist palette — blue, yellow, green, violet, orange, black — names routes and node kinds. Every hue is declared in a legend; red stays reserved for failure. Outside figures the page is still black, white and one red.

Objectivity is the tone. Müller-Brockmann called the style objective-informative: the designer's hand disappears behind the structure. A Basel report should read as if the facts arranged themselves.

Müller-Brockmann, Grid Systems in Graphic Design · 1981

04

Layout

The shell (.bsl-shell, alias .bsl-page) spans the viewport with a fluid gutter and stops only at 1920px. Prose keeps a 72-character measure so it stays readable on a wide screen; diagrams, tables, grids, code and stat strips take the full width, because that is where width earns its keep.

From 1200px, .bsl-layout sets a sticky contents rail (.bsl-toc) beside the content — the rail on the left of this page. Below 1200px the rail becomes a ruled list above the content. The current section is marked by a small inline script; without it, the rail is still a working list of links.

<div class="bsl-shell">
  <header class="bsl-masthead">…</header>
  <div class="bsl-layout">
    <nav class="bsl-toc"><div class="bsl-toc-h">Contents</div><ol><li><a href="#s1"><b>01</b>Context</a></li>…</ol></nav>
    <main><section class="bsl-section" id="s1">…</section></main>
  </div>
</div>

07

Architecture diagrams

Native SVG, drawn by hand on the grid: rectangles with radius 0, orthogonal edges, square packets. Routes and node kinds take the constructivist primaries; every hue used is declared in the legend, and red only ever means failure. Dashes march in the direction of travel and square packets ride the hot path — both stop under reduced motion.

FIG 01 — Container architecture

Zones are dashed boundaries; the heavy dashed frame is a trust boundary. Numbered squares on the edges key the figure to the walkthrough beneath it.

  1. Client → gateway. HTTPS with an Idempotency-Key header; the gateway enforces rate limits and validates the JWT against Identity's keys.
  2. Gateway → payments-svc. gRPC over mTLS into the PCI scope — the hot path.
  3. Claim the key. SET NX in Redis; a second request with the same key returns the stored result.
  4. Authorise with the PSP. Leaves the VPC; the key is forwarded so PSP-side retries are deduplicated.
  5. Publish. PaymentAuthorised to payments.events, keyed by wallet ID.
  6. Consume. ledger-writer reads the partition in order.
  7. Write the ledger. Double-entry rows in one transaction; after three failures the event goes to the proposed DLQ.

FIG 02 — Sequence: authorise with a PSP timeout

Lifelines are dashed, activations are open bars, solid arrows are calls, dashed grey arrows are returns. The red message is the failure; the yellow note states the rule that makes the retry safe.

FIG 03 — State machine: payment lifecycle

States are coloured by meaning, not by kind: blue in flight, green settled, red declined, grey closed by an operator; the yellow loop is a retry. Terminal states carry an inset frame.

Decision record

ADR-014

Claim idempotency keys in Redis, not Postgres

Accepted
Context

Clients retry on timeouts. Without a shared claim, two pods can authorise the same order. The claim must cost under 5 ms at p95 and expire on its own.

Decision

SET NX with a 24 h TTL in the existing Redis cluster, keyed by idem:<key>; the stored value is the final response, returned verbatim on replay.

Consequences
  • 3 ms claim at p95; no write amplification on Postgres.
  • Expiry is free — no sweeper job.
  • A Redis failover inside the window can admit one duplicate; the PSP key is the backstop.

Redis keys are namespaced per environment; staging cannot collide with production.

The PSP timeout of 3 s is shorter than the slowest 3-DS challenge. Raise it before enabling 3-DS 2.2.

A poison event blocks its partition until the DLQ ships. Owner: Ledger team, due 2026-10-20.

Idempotency keys live in Redis for 24 h. See ADR-014.

10

Mermaid fallback

Native SVG is the default for architecture, sequence and state. For shapes the grammar does not cover — ER, Gantt, pie — use Mermaid, themed through mermaid-config.json: white ground, black lines, red reserved for the one path that matters. Pre-render to static SVG and keep the DSL beside the figure in a <details> block.

npx -y @mermaid-js/mermaid-cli -i er.mmd -o er.svg --configFile mermaid-config.json
