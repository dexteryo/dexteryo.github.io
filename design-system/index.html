§ 01

Principles

Evidence over decoration. Every rule, colour, and label must encode something true about the content. Provenance — who verified what, when, against which source — is a first-class visual element, not a footnote.1

The accent means verified. There is one accent colour, a deep viridian, and it is the same colour as the sync hot path in diagrams and the ok status. Green is never decoration; when you see it, something is real or confirmed.

Colour is meaning, so use more of it. v2 gives every node kind and every route its own hue. A reader should be able to say "purple is a data write" without the legend after one diagram — and the legend is still mandatory.

Full width for evidence, a measure for prose. Diagrams, tables, and panels take the whole screen; paragraphs stay at 72 characters so they remain easy to read.

Portability is a hard constraint. System font stacks only, no webfonts, no external resources. Output must survive a sandboxed artifact viewer, an email attachment, a ticket, and a printer.

1. Inspired by the engineering title block: a drawing without a revision date and an approver is not a drawing, it is a sketch.

§ 03

Layout — full width, readable measure

The .dds-page shell is fluid: it spans the viewport with a responsive gutter and only stops at 1920px. Inside it, .dds-layout adds a sticky contents rail (.dds-toc) from 1200px; below that the rail folds into a wrapped list above the content. Prose, lists, callouts and timelines hold the 72ch measure; diagrams, tables, stat strips, card grids and panels take the full content width.

The FundWallet step is the only automated movement of real money in the estate: a single transfer from the platform float to the customer wallet.2 Every other record — the authorisation ledger, the double-entry journal — is a mirror. Mirrors can drift; the transfer cannot.

The one-way valve: money enters through five rails and leaves through one. The ledgers record a symmetry the money does not have.

§ 06

Architecture diagrams

Native inline SVG is the default for architecture, sequence and state diagrams. Nodes are <g class="dds-node kind"> groups — the kind picks the hue and the shape (cylinder for stores, barred box for queues, dashed for externals). Edges are .dds-edge paths whose route class picks colour and dash; .dds-flow marches the dashes in the direction of travel, and .dds-pkt dots ride the hot path. Motion stops under prefers-reduced-motion. Hover a node to lift it.

DWG 02-01 · Container view

Zones draw network and trust boundaries; numbered steps key the drawing to the walkthrough below it. The proposed balance-cache carries is-new; the dead-letter queue carries is-fail; the hot path service carries is-hot.

  1. The web checkout posts a payment intent through the API gateway (sync).
  2. The gateway verifies the caller's JWT with auth-service — control plane, never on the money path.
  3. The gateway routes to checkout-api, the only service inside PCI scope.
  4. checkout-api authorises the card at the PSP (third-party call, 190ms of the budget).
  5. checkout-api calls FundWallet on wallet-service.
  6. wallet-service writes the ledger row in one transaction; the unique key makes retries safe.
  7. wallet.funded is published asynchronously; nothing on the request path waits for it.
  8. recon-worker consumes events nightly and reconciles against the bank; poison messages go to recon.dlq.

DWG 02-02 · Sequence

Actors reuse the node kinds, so the sequence and the container view share colours. Solid arrows are calls, dashed grey arrows are returns, the red dashed arrow is a call that timed out, and notes explain the non-obvious.

DWG 02-03 · State machine

States are pills coloured by meaning; transitions reuse the route vocabulary — API commands are sync, PSP webhooks are async, timers are control-plane, failures are red.

The v1 funds-flow grammar still applies

For money-flow drawings where the semantics are money / manual / mirror / blocked, keep using .dds-diagram with .e-* and .n-* classes — see the diagrams reference. Mermaid remains the fallback for ER, gantt, class and the rest of the catalogue.

Decision record

ADR-014

Enforce idempotency in the ledger, not the gateway

Accepted 2026-09-18 · payments-core
Context

PSP timeouts trigger client retries. A gateway-level dedupe cache lost keys on eviction and double-funded 14 wallets in August.

Decision

A unique constraint on (wallet_id, idempotency_key) in ledger-db; inserts use ON CONFLICT DO NOTHING and return the original row.

Consequences
  • Exactly-once funding survives cache loss and region failover.
  • No new infrastructure.
  • One extra index write per payment (≈2ms).
  • Keys must be retained for 35 days.
