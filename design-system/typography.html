Typography

Three faces, three jobs: serif argues, sans operates, mono testifies. All from system stacks — the output must survive a sandbox, an email, and a printer.

§ 01

The three roles

TokenStackJob
--dds-serifIowan Old Style · Palatino Linotype · Palatino · GeorgiaDocument-mode prose and headings. The voice of the argument.
--dds-sanssystem-ui (SF Pro / Segoe UI / Helvetica / Arial)Panel-mode UI and diagram node labels. The voice of the instrument.
--dds-monoSF Mono · ui-monospace · Cascadia Code · Menlo · ConsolasMachine truth: code, identifiers, timestamps, evidence citations, eyebrows, table headers, metadata.

Monospace is semantic, not decorative. When a value comes from a machine — an ID, a path, a timestamp, a version — it is set in mono. When a human wrote it, it is not. This one rule does more for scannability than any amount of colour.

§ 04

Rules

  • Measure: prose ≤ 66ch, always. Wide layouts get more columns, not longer lines.
  • Numbers: any digit column gets .dds-num (tabular numerals), right-aligned in tables.
  • Uppercase: only mono labels are uppercase, and always letter-spaced (+0.06em to +0.16em). Never uppercase serif or body sans.
  • Emphasis: at most one <em> accent in a title; <strong> for lead-in phrases, never whole paragraphs.
  • Headings: text-wrap: balance on titles; section numbers (§ 01) only when order carries meaning.
  • No webfonts: no @font-face, no font CDN. If a platform lacks Iowan Old Style, Palatino or Georgia carries the page — the stacks are chosen so every fallback stays in character.
